# 製品概要

[English](product.md)

## 1. 概要

TakeBinderは、GoProで撮影したフォルダを指定すると、同一の録画がファイルサイズ上限などにより複数ファイルへ分割された「チャプター」を検出し、録画単位で1本のMP4へまとめて整理するデスクトップアプリケーションである。

映像と音声は再エンコードせず、GoPro固有のGPMFトラックに含まれるジャイロ、加速度、GPSなどのテレメトリを保持する。複数の録画グループは並列処理し、結合対象が1ファイルしかない場合はメディア処理を行わず、そのファイルをそのまま出力する。

## 2. 用語

Osmo Pocket / DJIの試験対応ではMP4をファイル単位でコピー・整理する。DJIの録画全体の判定や結合は行わない。[対応範囲・調査・未検証事項](osmo-pocket-support.md)を参照する。以下のキャプチャ関連用語はGoProのグループ判定を説明する。

| 用語 | 定義 |
| --- | --- |
| キャプチャ | GoProで録画開始から録画停止までに生成された1回分の撮影 |
| チャプター | 1回のキャプチャが複数のMP4へ分割されたときの各ファイル |
| 撮影グループ | 同一キャプチャに属する1個以上のチャプターの集合 |
| GPMF | GoPro Metadata Format。ジャイロ、加速度、GPS、カメラ情報などを格納するMP4内の時系列メタデータ |
| パススルー | 入力ファイルをメディア変換せず、バイト列を維持したまま出力先へコピーする処理 |
| ストリームコピー | 映像・音声をデコード／再エンコードせず、新しいMP4コンテナへ格納する処理 |

初期要望の「キャプションごと」は「同一キャプチャ（撮影グループ）ごと」の意味として扱う。

## 3. 目的

- 大量のGoPro動画を、ユーザーが個別に選別せず録画単位へ整理できること。
- 映像・音声の品質を一切劣化させないこと。
- Gyroflowなど後工程で利用するGoProのGPMFテレメトリを失わないこと。
- Windows、macOS、Linuxで同じ操作性を提供すること。
- 大量ファイルを撮影グループ単位で並列処理し、待ち時間を短縮すること。
- 入力ファイルを変更・削除せず、安全に処理できること。

## 4. 対象範囲

### 4.1 MVPに含める機能

- 入力フォルダと出力フォルダの指定
- サブフォルダを含むMP4ファイルの走査
- GoProファイルかどうかの判定
- 同一キャプチャに属するチャプターの自動グループ化
- チャプター順序の自動決定
- 撮影グループ単位の並列処理
- 複数チャプターの無劣化結合
- 単独ファイルのパススルーコピー
- GPMFトラックの保持と処理後検証
- 進捗、成功、警告、失敗理由の表示
- 処理キャンセル
- 実行結果レポートの保存
- 撮影日時ごとの出力フォルダ作成
- 元動画を出力フォルダ内の `original` へコピーする任意設定
- 出力ファイルへの先頭チャプターの撮影日時引き継ぎ
- Windows、macOS、Linux向けアプリケーション配布
- Yarn依存、CI、同梱バイナリを対象としたサプライチェーン保護

### 4.2 MVPに含めない機能

- H.264とH.265間の変換
- 解像度、フレームレート、ビットレートの変更
- 手ぶれ補正の適用
- フレーム単位の編集や任意位置でのカット
- 動画プレビューおよびタイムライン編集
- クラウドへのアップロード
- 入力ファイルの移動または削除
- 360度動画のスティッチ処理
- 独自パッケージレジストリや独自セキュリティ監視基盤の運用

## 5. UI要件

MVPは「変換」と「設定」の2ページを基本とする。変換ページは日常操作だけに絞り、詳細な動作指定とツール管理は設定ページへ置く。
入力・出力フォルダと設定ページの値は、次回起動時に復元する。

1. 入力フォルダ選択（ダイアログ／ドラッグ＆ドロップ、前回値を保持）
2. 出力フォルダ選択（ダイアログ／ドラッグ＆ドロップ、前回値を保持）
3. 設定ページの走査・出力オプション
   - サブフォルダを含める
   - 出力構造を集約／維持
   - SHA-256による厳密検証
   - 最大並列数
   - 撮影日ごとのフォルダ作成とフォルダ名形式（`{YYYY}`、`{MM}`、`{DD}`。既定値 `{YYYY}-{MM}-{DD}`）
   - JSONレポート生成の有効／無効
   - 元動画を `original` へコピー
   - 先頭チャプターの撮影日時を出力へ引き継ぐ
4. 「解析」ボタン
5. 撮影グループ一覧
   - 出力予定名
   - チャプター数
   - 合計容量と時間
   - 撮影日時と解像度
   - GPMFの有無
   - 判定状態
6. 「処理開始」ボタン
7. 撮影グループ別プログレスバー
8. ログと完了サマリー

解析結果をユーザーが確認してから処理を開始する2段階方式とする。
