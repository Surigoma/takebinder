# 機能要件

[English](functional-requirements.md)

## FR-01 フォルダ選択

1. ユーザーは入力フォルダと出力フォルダをGUIから選択できる。
2. 入力フォルダと出力フォルダは、選択ダイアログまたはドラッグ＆ドロップで指定でき、次回起動時に前回値を復元する。
3. サブフォルダ走査は既定で有効とし、設定で無効にできる。
4. 入力フォルダと出力フォルダが同一、または出力が入力配下の場合は、出力済みファイルを再走査しない。
5. 入力ファイルは読み取り専用として扱い、上書き、移動、削除を行わない。
6. 設定ページで変更した値は保存し、次回起動時に復元する。
7. ユーザーは確認操作の後、表示言語と設定ページの変換設定を初期値へ戻せる。入力フォルダと出力フォルダの保存値は保持する。

## FR-02 ファイル検出

1. 拡張子が `.mp4` または `.MP4` のファイルを候補とする。
2. MP4のトラック構成とメタデータを検査し、GoPro由来かを判定する。
3. 判定結果を次のいずれかに分類する。
   - GoPro動画かつGPMFあり
   - GoPro動画だがGPMFなし
   - 機種メタデータで判定したOsmo Pocket（`osmo-pocket`、コピーのみ）
   - メーカー情報またはファイル名から推定したDJI候補（`dji-candidate`、コピーのみ）
   - GoPro以外のMP4
   - 破損または解析不能
4. 既定ではGPMF付きGoPro動画を処理対象とする。試験対応のDJIでは、検証済みの連続性条件を満たすPocket 4分割だけを結合し、その他のDJI MP4は1ファイルずつコピーする。その他はスキップして理由を表示する。
5. Pocket機種メタデータは `osmo-pocket`、DJIメーカー情報またはファイル名の候補判定は `dji-candidate` とする。ファイル名だけで機種や録画の区切りを確定しない。判定規則・出典・未検証事項は [Osmo Pocket / DJI対応状況](osmo-pocket-support.md) を参照する。

## FR-03 撮影グループ判定

撮影グループの判定には、信頼度の高い情報から次の優先順位を用いる。

1. GPMFまたはMP4メタデータ内のMedia ID、Capture ID、Chapter情報
2. GoProのファイル命名規則に含まれる撮影番号とチャプター番号
3. カメラモデル、コーデック、解像度、フレームレート、作成時刻、連続性による補助判定

異なるキャプチャを誤って結合する可能性がある場合、自動結合せず「要確認」とする。ファイル名だけから不確実な推測を行った場合は、UIに判定根拠と信頼度を表示する。

DJI候補は汎用Capture ID/Chapterタグがあっても低信頼の `DJI file copy` 単位とする。確定したPocket 4は、厳密な名前、連番、分割サイズ、ファイル名時刻とSMPTEタイムコードの連続性、同一ディレクトリ、全ストリーム構成がすべて一致した場合だけ `DJI Pocket 4 split continuity` としてグループ化する。その他のDJI複数ファイル単位は `E_GROUP_AMBIGUOUS` で拒否する。

## FR-04 チャプター順序

1. 明示的なチャプター番号を最優先する。
2. チャプター番号が取得できない場合のみ、MP4の開始時刻とファイル名を補助的に用いる。
3. 番号の欠落、重複、時系列の逆転を検出した場合は警告する。
4. 順序を確定できないグループは自動処理しない。

## FR-05 互換性事前検査

結合前に、同一グループ内で少なくとも次を比較する。

- 映像コーデックとプロファイル
- 解像度
- フレームレートおよびタイムベース
- 色空間、HDR関連情報
- 音声コーデック、サンプルレート、チャンネル構成
- GPMF `gpmd` トラックの有無
- タイムコードおよび各トラックの継続性

ストリームコピーで安全に結合できない組み合わせは、再エンコードへ自動フォールバックせず失敗として報告する。

## FR-06 複数チャプターの結合

1. 映像と音声はストリームコピーし、再エンコードしない。
2. GPMFトラックのペイロードと時刻情報を、チャプター順に連結する。
3. 必要に応じてタイムコードトラックも連結または再構成する。
4. 完成ファイルはMP4形式とする。
5. 一時ファイルへ出力して検証に成功した後、最終ファイル名へ確定する。
6. 失敗時に不完全なファイルを完成品として残さない。

## FR-07 単独ファイルの扱い

1. 撮影グループが1ファイルのみの場合、結合やリマックスを行わない。
2. 入力と出力が別の場所なら、ファイルをバイト単位でコピーする。
3. コピー後にファイルサイズを比較し、オプション設定に応じてSHA-256も照合する。
4. 更新日時は可能な範囲で元ファイルから引き継ぐ。
5. 入出力が同一実体を指す場合はコピーせず、「変更なし」として完了する。

## FR-08 並列処理

1. 並列化の単位は撮影グループとする。
2. 同一グループ内のチャプターは順序を守って処理する。
3. 既定の同時実行数は `min(4, 論理CPU数の半分、撮影グループ数)` とする。
4. ユーザーは同時実行数を1～8の範囲で変更できる。
5. ストレージ負荷を考慮し、入力と出力が同一ストレージ上の場合は既定値を最大2へ抑制する。ユーザーが明示した並列数は1～8の範囲で優先する。
6. UIは撮影グループ単位の進捗を表示する。
7. 1グループの失敗は、独立した他グループの処理を停止させない。

## FR-09 出力

1. 既定のファイル名は、元キャプチャを識別できる名称と撮影日時から生成する。
2. 例: `2026-08-09_143052_GX012345.mp4`
3. 同名ファイルがある場合は上書きせず、`_2`、`_3`のような連番を付ける。
4. サブフォルダ構造を保持するか、出力直下へ集約するかを選択できる。既定は出力直下への集約とする。
5. ファイル名に使用できない文字はOSごとに安全な文字へ置換する。
6. ユーザーは撮影日ごとのフォルダへ出力するか選択できる。フォルダ名はファイル名と同じ波括弧付きの `{YYYY}`、`{MM}`、`{DD}` を使って指定でき、既定値は `{YYYY}-{MM}-{DD}` とする。波括弧で囲まれていない文字列は置換しない。同じ日に撮影したグループは同じフォルダへまとめる。パス区切り文字など、フォルダ名として安全でない形式は拒否する。保存済みの旧形式は波括弧付きへ移行する。
7. 撮影日時は先頭チャプターの動画メタデータにある撮影開始日時を優先し、取得できない場合は先頭チャプターのファイル更新日時へフォールバックする。どの値を採用したかをレポートへ記録する。
8. ユーザーは各撮影日フォルダ内の `original` フォルダへ、その日の元動画をコピーするか選択できる。この設定は既定で無効とする。
9. `original` への保存はコピーのみとし、入力ファイルの移動、変更、削除を行わない。開始前に追加で必要となる容量を表示し、空き容量不足時は処理を開始しない。
10. 元動画コピーの名前が競合する場合は暗黙に上書きせず、入力との同一性を検証するか安全な連番名を採用する。
11. 出力動画には既定で先頭チャプターの撮影日時を引き継ぐ。動画コンテナ内の撮影日時とファイル更新日時を設定し、対応OSではファイル作成日時も設定する。
12. 日時の設定可否はOSとファイルシステムに依存するため、設定できなかった項目は警告およびレポートへ記録する。日時設定の失敗だけを理由に、内容検証済みの動画を破損扱いにはしない。
13. 日付フォルダとサブフォルダ構造維持を併用する場合、`日付/入力の相対サブフォルダ/動画` の順に配置する。`original` は従来どおり日付フォルダ直下に置く。
14. ユーザーは設定ページでファイル名形式を指定できる。`{YYYY}`、`{MM}`、`{DD}`、`{hh}`、`{mm}`、`{ss}`、`{NAME}`（先頭チャプターの拡張子を除いた名前）を使用し、既定値は `{YYYY}-{MM}-{DD}_{hh}{mm}{ss}_{NAME}` とする。波括弧で囲まれていない文字列は置換しない。拡張子 `.mp4` は自動付与し、設定を次回起動時へ保存する。パス区切り文字を含む形式は拒否し、OSで使用できない文字は安全な文字へ置換する。

## FR-10 処理後検証

結合結果について次を検証する。

- 出力MP4が解析可能であること
- 映像、音声、GPMFの必須トラックが存在すること
- 映像と音声のコーデックが入力と一致すること
- 出力時間が入力チャプターの合計と許容誤差内で一致すること
- GPMFのサンプル期間が動画全体を覆うこと
- GPMF内に入力に存在した主要キー（例: `GYRO`、`ACCL`、`GPS5`）が存在すること
- 入力と出力の映像・音声パケットが再エンコードされていないこと

検証に失敗した出力は完成扱いにしない。元ファイルは常に保持する。

## FR-11 キャンセルと再実行

1. ユーザーは処理全体をキャンセルできる。
2. 実行中の外部プロセスを安全に終了し、一時ファイルを未完成として扱う。
3. 完了済みファイルは削除しない。
4. 再実行時は既存の実行結果レポートと出力を確認し、完了済みグループをスキップできる。

## FR-12 レポート

レポート生成は既定で有効とし、ユーザーは設定ページで無効にできる。有効な場合、処理終了後に出力フォルダへJSON形式のレポートを保存する。無効な場合はレポートファイルを作成しない。レポートには次を含める。

- アプリとバックエンドのバージョン
- 実行開始・終了時刻
- 入力・出力フォルダ
- 検出ファイル数と撮影グループ数
- 各グループの入力ファイル、順序、判定根拠
- 結合、パススルー、スキップ、失敗の結果
- 入出力のストリーム情報
- GPMF検証結果
- 撮影日時の取得元、日時設定警告
- エラーコードと診断メッセージ

## エラー方針

| コード | 状況 | 動作 |
| --- | --- | --- |
| `E_INPUT_UNREADABLE` | 入力を読めない | 対象を失敗として継続 |
| `E_NOT_GOPRO` | GoPro動画でない | スキップ |
| `E_GROUP_AMBIGUOUS` | グループ判定が不確実 | 自動処理せず要確認 |
| `E_CHAPTER_GAP` | チャプター欠落 | 警告し、既定では処理しない |
| `E_STREAM_MISMATCH` | ストリーム非互換 | 再エンコードせず失敗 |
| `E_GPMF_MISSING` | 必要なGPMFがない | 失敗または入力状態に応じた警告 |
| `E_GPMF_VERIFY` | 出力GPMF検証失敗 | 出力を完成扱いにしない |
| `E_OUTPUT_EXISTS` | 出力名競合 | 安全な連番名を採用 |
| `E_DISK_FULL` | 空き容量不足 | 新規ジョブを停止し報告 |
| `E_CANCELLED` | ユーザーキャンセル | 一時出力を完成扱いにしない |
| `E_TOOLS_BUSY` | ツールを使用中または変更中 | 取得・削除を拒否し、処理完了後に再試行 |
| `E_TOOL_REMOVE` | 管理ツールを完全に削除できない | 失敗を報告し、状態を再取得 |

## FR-13 外部ツール取得

1. ユーザー操作で `ffmpeg`、`ffprobe`、`mp4-merge` の固定版単体バイナリを取得できる。
2. URL、バージョン、期待サイズ、SHA-256はアプリ内に固定し、ユーザー入力やリモートmanifestを受け付けない。
3. HTTPSおよび許可済みホストだけを使用し、リダイレクト先にも同じ制約を適用する。
4. サイズまたはSHA-256が一致しないファイルは利用せず、一時ファイルを削除する。
5. `ffmpeg` と `ffprobe` はアプリ管理領域から優先的に利用する。
6. 各ツールは `-version` が成功した後に利用可能とする。インストーラーやパッケージマネージャーは実行しない。
7. 設定画面から、確認後に取得済みFFmpeg・ffprobe・mp4-mergeを削除できる。削除対象はアプリ管理領域内の専用 `ffmpeg` / `ffprobe` / `mp4_merge` 配下に限定し、旧バージョンと途中のダウンロードも含める。PATH上の別途導入したツール、入力・出力動画、その他の領域は削除しない。シンボリックリンクがあっても管理ルート外へ走査しない。
8. 取得と削除は相互排他とし、動画の解析・処理とも重ねない。競合要求は `E_TOOLS_BUSY` で拒否し、UIでも処理中の操作を無効にする。`remove-tools` の入力は空オブジェクトのみとし、パスは受け付けない。成功時は `tools.remove.completed` と最新のツール状態を返す。状態の `removable` は、利用可否やチェックサムと独立して管理下のツール項目の有無を表す。
9. 削除時は走査計画を破棄する。成功・失敗のどちらでもツール状態を更新し、失敗は `E_TOOL_REMOVE` で報告する。一部しか削除できなかった状態を成功扱いにしない。固定版ツールは再取得できる。管理版の削除後も別途導入したツールが利用可能な場合がある。

## FR-14 表示言語

1. UIは日本語と英語を選択できる。
2. 保存済みの選択がない初回起動では、OS言語が日本語なら日本語、それ以外は英語を使用する。
3. 選択した表示言語は即時反映し、次回起動時へ保存する。
